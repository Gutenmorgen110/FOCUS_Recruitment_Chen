## 一、考核内容一：基础政策与原则

请认真阅读并理解以下基础政策和原则，确保不违背本次招新的根本精神。

### 1.1 考核目标

满足以下要求**之一**即可：

1. 选拔出具有**自驱力**、对机器人方向怀有足够热爱，愿意在此领域投入大量时间和精力的人才（而非过于功利、唯加分或评奖评优论者）。
2. 选拔出**敢于尝试**、不墨守成规，愿意在大学阶段积极探索技术、创业或科研方向的人才。
3. 选拔出具备**组织、表达、团结与领导能力**，能够带动身边队友共同进步、协调项目进度的人才。
4. 选拔出**深造意愿强烈**，对攻读博士、从事科研工作充满热情的人才。

### 1.2 出题原则

1. 假定参与考核的同学为有志于往机器人方向发展的**大学一年级新生**。考核内容旨在补全机器人从业者及机器人专业学生所必需且共通的**底层能力与视野**，帮助其对未来的机器人学习路线形成初步规划。
2. 假定学生具备**科学上网能力**，并能够使用 **AI 工具**（若尚不具备，需主动向周围同学请教学习）。
3. **不假定**学生具备中等及以上的基础能力（即不假定其在高中参加过机器人或信息学相关竞赛，或接触过任何编程语言）。

### 1.3 AI 使用政策（AI Policy）

1. 本说明适用于本次考核**全程及全部内容**。
2. 你可以、也应当将 AI 视为**能力远超于你的协作者或老师**，应经常向其请教问题，将其作为你最得力的帮手。
3. 但在此次考核中，你**绝不能将自己定位为产品经理、将 AI 定位为工程师来直接交付结果**，否则你将无法从中获得真正的成长。
4. 请不要完全依赖 Codex、Claude Code 等 AI 代码工具生成代码，而自身对基础细节一无所知。面试时将考察原理、应用等方面的内容。
5. 对于环境配置等问题，你可以尽情地使用 AI。
6. 所有人所使用的 AI 能力相同或接近，**真正区分你与他人的，是基本功**。

### 1.4 本套试题使用方式

1. 以下部分分为**强化**学习**、**嵌入式基础**、**ROS 2 机器人仿真与视觉**、**电路基础**四大部分，每个部分均有若干个 Task。四大部分分别聚焦算法、嵌入式控制、机器人软件与视觉、电路设计四大控制组细分岗位。对于基础薄弱的大一同学，建议根据自己的爱好，**专精一大项**完成。对于大二的同学，建议选择**两大项及以上**完成。
2. 当然，做哪部分的题目不代表你以后在项目中要从事哪种特定类型的工作，我们欢迎同学们拓展自己兴趣的**广度与深度**，甚至成为**全栈工程师**。

# 三、嵌入式基础

### 任务目标

   学习嵌入式开发的工具链、了解嵌入式开发的完整流程，学习基础接线方法。

   使用 Arduino IDE 和 ESP32 Arduino Core 完成从 GPIO、PWM 到通信与状态机的实践，理解嵌入式开发的基本概念并完成任务。

   本篇为 ESP32 Arduino 嵌入式开发方向专属笔试题，聚焦 ESP32 硬件原理、Arduino 固件开发、外设控制、物联网应用等核心考点，全面检验你的嵌入式开发能力。

   任务使用 Arduino 语言（C/C++）和 Arduino Core for ESP32 提供的常用 API，先快速实现功能，再逐步理解底层原理。

本部分提供 **两个开发方向**，**二选一**完成即可：**方向一：ESP32 Arduino**（Arduino IDE，见上文）；**方向二：ESP-IDF**（乐鑫官方框架，更贴近底层驱动，见下文‘方向二：ESP-IDF’）。其中，**大二同学限定只能选择方向二完成**。

### 方向一：ESP-Arduino

   ESP32 是由乐鑫信息科技推出的高集成度、低功耗 32 位物联网系统级芯片（SoC），集成 2.4GHz Wi-Fi 与蓝牙双模通信模块，

   拥有丰富的外设接口与完善的开发生态，兼具高性能与低功耗特性，广泛应用于智能硬件、物联网终端、嵌入式控制等场景，

   是嵌入式物联网开发中极具代表性的主流平台。

##### 任务介绍

   本次笔试题从易到难分为**6个TASK**，请各位按顺序逐步完成。**ATTENTION**：

- 基础要求：只要求为每个Task编写独立demo验证功能。**但是：**可最终提交**整合版工程**，兼容所有已完成Task的点灯方式（即支持多模态控制并存，无功能冲突），则是加分项。整合版工程建议大二同学做到。
- github仓库请写一篇简要的README.md介绍你的作品。
- 所布置任务完成程度（进度、效果）会影响最终得分。
- 其中TASK6是扩展题，大二同学需完成，大一同学不做要求。

  以下是各个**任务说明**：
- **TASK1：物资准备、环境安装及验证：**

  安装 Arduino IDE，配置ESP32 开发环境。

  可参考上方视频与文档教程完成驱动、开发板和串口配置。

  配置好环境后，连接硬件，使用 Arduino API，编写并上传第一个程序，点亮你的 LED。
- **TASK2：改进你的灯为呼吸灯**：

  PWM（脉冲宽度调制）是嵌入式开发中实现 “模拟量调节” 的核心技术 —— 它通过控制高低电平的占空比，将数字信号模拟为连续变化的电压 / 电流，这也是调节 LED 亮度的核心原理。

  本任务中，你需要先理解 PWM 的工作机制（占空比、频率与输出电平的关系），再使用 Arduino ESP32 的 LEDC/PWM API，

  将普通的亮灭灯改为**呼吸灯**：实现 LED 亮度在设定范围内平滑渐变（从暗到亮、再从亮到暗循环）。
- **TASK3：实现有线协议点灯：**

  串口（UART）协议是嵌入式设备中最基础、最通用的有线通信方式之一。

  你需要掌握波特率、数据位、停止位、校验位等基本概念，并配置串口、收发数据，最终实现**通过串口指令控制 ESP32 开发板**完成 LED 亮灭与亮度控制。

  指令格式自行设计，但需在 README 中说明。
- **TASK4：实现无线协议点灯：**

  ESP32 能风靡全球的原因离不开它原生的无线通信功能。

  使用 Arduino ESP32 提供的 Wi-Fi 与 Bluetooth/BLE 库，实现无线联动控制灯的明灭与亮暗。

  1. 蓝牙：学习 BLE 的 GAP/GATT 基础，使用 Arduino 的 BLE 库创建服务和特征，通过手机发送指令控制 LED。蓝牙配网可作为拓展，不作必备要求。
  2. 网络：了解 IP、端口、Socket 等基本概念，使用 `WiFi.h` 连接路由器并完成简单的 TCP/HTTP 通信；有余力可使用 PubSubClient 等库接入 MQTT，实现远程控制。
- **TASK5：状态机编程**

  在 Arduino 工程中，循环函数 `loop()` 会持续处理传感器、串口和网络事件。将这些事件组织成有限状态机，可以让程序在功能增加后仍保持清晰、可维护。

  状态机（有限状态机 FSM）将设备逻辑拆解为若干离散状态（如“熄灭”“常亮”“呼吸”“闪烁”“联网中”“已联网”），并定义串口指令、按键、Wi-Fi 状态和定时器等事件触发状态切换的规则。

  建议使用 `millis()` 实现非阻塞定时，避免在 `loop()` 中长时间 `delay()` 阻塞其他功能。

  你需要实现状态机的编程，将 LED 的 “熄灭 / 常亮 / 呼吸 / 闪烁” 等作为核心状态，把 "串口指令、网络连接、MQTT 指令、定时器事件" 等作为状态切换的触发事件，自行设计并实现一套基于状态机的灯控逻辑。
- **TASK6（扩展题）：使用 TFT 屏幕实现创意功能**

  TFT 屏幕能够显示文字、图形、图片和动画，是嵌入式设备与用户交互的重要窗口。本任务要求你使用 ESP32-S3 驱动 TFT 屏幕，并在此基础上自行构思、设计和实现一个具有完整效果的创意功能。

  创意方向不限。例如：制作联网时钟或天气界面、播放动画或动态视频、绘制实时数据曲线、制作电子相册、小游戏、设备状态仪表盘，或将屏幕与前面任务中的灯光、串口、蓝牙和网络功能联动。以上仅为示例，我们更期待你实现自己的想法。

  **基础要求：**

  1. 根据所用屏幕的型号和通信接口正确完成接线，使 ESP32-S3 能够稳定驱动 TFT 屏幕。
  2. 屏幕应至少能够正确显示文字、图形或图片，并在此基础上实现一项完整的创意功能，而非仅运行图形库自带的示例程序。
  3. 动态内容应连续、稳定地运行；程序不应出现明显卡死、频繁闪屏或异常重启。
  4. 在 README 中说明屏幕型号、引脚连接、所用图形库、功能设计和使用方法，并附上能够展示实际运行效果的图片或视频。

  **建议探索：**

  - 了解所用 TFT 屏幕的分辨率、色彩格式及 SPI 或其他通信方式的基本原理。
  - 思考图片、字体或视频帧如何存储和读取，并合理利用 ESP32-S3-N16R8 的 Flash 与 PSRAM。
  - 对动态界面合理控制刷新区域和刷新频率，尝试减少闪烁、撕裂与不必要的全屏刷新。
  - 尝试让屏幕与 Wi-Fi、BLE、串口、按键或已有灯控系统产生交互。

  本任务不以界面复杂程度作为唯一评价标准。创意的完整性、实际运行效果、对实现原理的理解，以及解决调试问题的过程同样重要。

##### TASK2：改进你的灯为呼吸灯 —— LEDC PWM

PWM（脉冲宽度调制）是嵌入式开发中实现 "模拟量调节" 的核心技术 —— 它通过控制高低电平的**占空比**，将数字信号模拟为连续变化的电压 / 电流，这也是调节 LED 亮度的核心原理。

本任务中，你需要先理解 PWM 的工作机制（**频率、分辨率、占空比**三者的关系），再基于 ESP-IDF 的 **LEDC 驱动接口**（`ledc_timer_config` + `ledc_channel_config`），将普通的亮灭灯改造为**呼吸灯**：实现 LED 亮度在设定范围内平滑渐变（从暗到亮、再从亮到暗循环），直观体会 PWM 在硬件控制中的实际应用。

> 注：TASK5 电机调速用的也是 LEDC，两者原理完全一致，只是频率和驱动对象不同。

##### TASK3：实现有线协议点灯 —— UART 串口

* 使用 `uart_driver_install()` 配置串口（建议 115200, 8N1）；

**一、基础任务：普通直流电机控制**

1. **硬件接线与供电**

* 驱动模块二选一：

  * **L9110S**（最简）：IN1 / IN2 接两个 GPIO；启停 / 正反转用 GPIO 电平（IN1=1、IN2=0 正转，反之反转，同电平停止），PWM 调速时 IN1 接 PWM、IN2 接方向电平（或互换）；
  * **TB6612**（推荐，可扩双路）：PWMA 接一个 GPIO（PWM 调速），AIN1 / AIN2 接两个 GPIO（方向）。
* 供电：5V 电源单独给驱动模块供电，开发板与驱动**共地**（GND 相连）；严禁用开发板 3.3V 直驱电机。

1. **GPIO 驱动电机启停**

* 配置 2 个 GPIO 为**推挽输出（无上下拉）**，用 `gpio_set_direction()` + `gpio_set_level()` 控制 IN1/IN2（或 AIN1/AIN2），实现电机启停与正反转。
* 验证标准：电机稳定启停、无卡顿 / 异响，驱动芯片与电机无异常发热。

1. **PWM 无级调速**

* 用 **LEDC**（`ledc_timer_config()` + `ledc_channel_config()`，思路与 TASK2 呼吸灯完全一致，只是频率与负载不同）输出 PWM 到驱动模块，理解 **占空比 → 等效电压 → 电机转速** 的链路。
* 相比 GPIO 直接驱动，PWM 调速能避免电机瞬间大电流堵转，提升控制精度。
* **实现转速自动渐变：慢 → 中 → 快 → 中 → 慢 循环**（禁止用阻塞延时写死）。参考做法：FreeRTOS 任务中按档位周期更新占空比（`ledc_set_duty()` + `ledc_update_duty()`），或使用 LEDC fade 渐变接口。

1. **串口控制电机**

* 沿用 TASK3 的 UART **中断接收 + 环形缓冲**（避免轮询占用 CPU），指令格式自行设计并在 README 说明，示例：

| 指令                  | 说明                                       |
| --------------------- | ------------------------------------------ |
| `ON` / `OFF`      | 启动 / 停止电机（停止时占空比置 0）        |
| `SPEED 50`          | 设置转速（参数 0~100，对应占空比 0%~100%） |

**二、拓展任务：编码器电机 + PID 速度闭环**

> 学习参考：

> [配套演示视频](https://www.bilibili.com/video/BV18Q4y1R7e8)

1. **编码器测速**

* 换用**带编码器的 TT 马达**（购买时务必与客服确认带编码器）。理解编码器测速原理：电机每旋转一周，编码器输出固定数量的脉冲，统计单位时间内的脉冲数即可换算实际转速：

```
RPM = 采样周期内脉冲数 ÷ 每转脉冲数 ÷ 采样时间（分钟）
```

示例：编码器每转 20 个脉冲，采样 100ms 数到 50 个脉冲，则 RPM = 50 ÷ 20 ÷ (0.1/60) = 1500。

* 使用 ESP32-S3 内置 **PCNT 外设**（硬件脉冲计数，等价于 STM32 的 "定时器编码器模式"：倍频更高、采样更精确、CPU 占用更低；GPIO 外部中断法也可尝试，但有高频中断导致 CPU 占用过高的风险）。用 `pcnt_unit_config()` / `pcnt_channel_config()` 配置计数单元与输入滤波，定时 `pcnt_unit_get_count()` 读取计数并 `pcnt_unit_clear_count()` 清零。
* 在 README 记录：编码器线数 / 圈、倍频方式、脉冲计数与转速换算公式。

2. **PID 精准转速闭环**

* 理解 PID 三要素：**P（比例）**—— 按偏差成比例输出，快速消除偏差；**I（积分）**—— 累积历史偏差，消除稳态误差；**D（微分）**—— 预测偏差变化趋势，抑制超调，但对噪声敏感（速度环可只用 PI）。
* 控制回路：`目标转速 − 实际转速（PCNT 测得）→ PID 计算 → 更新 PWM 占空比`，控制周期建议 10~50ms。
* **参数整定方法（先 P 后 I）**：

1. 令 I=0、D=0，P 从小到大逐步加大，观察转速阶跃响应，取 "开始明显震荡前 P 值的 50%~60%" 作为 P；
2. 加入 I 并逐步增大，消除稳态误差（若出现低频振荡则减小 I）；
3. 记录每组 P/I 对响应速度、超调量、稳态误差的影响，把整定过程写进 README。

* **验证方法**：串口发送 `SET_RPM 250`，串口持续实时输出 `目标转速：250 → 实际转速:xxx`，观察转速从变化到稳定的快慢（阶跃响应）、稳态误差与超调情况。

3. **README 要求**：记录编码器分辨率、测速公式、PID 参数（P/I 值）与整定过程、调试中遇到的问题与解决方法。

# 四、机器人仿真与视觉

### 任务目标

配置 Ubuntu 与 ROS 2 开发环境。

了解 ROS 2 的基本工作方式，掌握工作空间构建、节点运行、Topic 通信、TF 坐标变换和常用调试工具；在 Gazebo 中完成移动机器人与仿真环境的设计，使用激光雷达进行 SLAM 建图，并利用传感器数据实现简单的自主探索和视觉目标跟随。

本部分提供一个可运行的差速移动机器人仿真起始工程，位置为：

```text
part3/ROS2-Recruitment-Starter-main/recruit_robot_sim
```

起始工程已经提供机器人基本模型、Gazebo 场景、差速驱动、激光雷达、RGB 相机、里程计、TF、RViz 和 SLAM Toolbox 配置，但**不包含**自主探索、颜色跟随、路径规划或现成的自主导航程序。你需要阅读工程和相关文档，在此基础上独立完成以下任务。

### 环境要求

- Ubuntu 22.04
- ROS 2 Humble
- Gazebo Classic 11 与 `gazebo_ros_pkgs`
- `slam_toolbox`、`teleop_twist_keyboard`
- OpenCV 与 `cv_bridge`

Windows 用户推荐使用 **WSL2 + Ubuntu 22.04** 配置环境；也可以使用原生 Ubuntu 22.04。请勿使用 WSL1。使用 Windows 11 时可通过 WSLg 运行 Gazebo、RViz 等 Linux 图形程序，并建议先将 WSL 更新至最新版本。如果当前设备无法正常运行 WSLg，或 Gazebo 图形界面存在严重兼容性问题，可以改用原生 Ubuntu 环境。

### 任务介绍（推荐阅读英文原文`part3/ROS2-Recruitment-Starter-main/recruit_robot_sim/README.md`）

- **TASK1：配置环境、运行并理解基础工程**

  首先完成 Ubuntu 22.04、ROS 2 Humble、Gazebo Classic 11 及本题所需依赖的安装。

  建议自行学习并配置 WSL2，理解 Windows、WSL2 和 Ubuntu 三者之间的关系，以及如何进入 Linux 终端、访问文件和运行图形程序。

  按照起始工程`ros/ROS2-Recruitment-Starter-main/recruit_robot_sim/README.md`的说明创建 ROS 2 工作空间、放置功能包并使用 `colcon build` 完成编译。

  正确加载 ROS 2 和工作空间环境后，启动 Gazebo 与 RViz，确认机器人模型、激光雷达数据和相机画面均能正常显示。不得仅展示安装完成页面，应以工程实际成功运行作为环境配置完成的标准。

  成功启动起始工程后，使用 `teleop_twist_keyboard` 控制机器人运动。在 RViz 或 ROS 2 命令行工具中查看并理解 `/cmd_vel`、`/scan`、`/odom`、`/camera/image_raw` 和 `/map` 等 Topic 的数据及作用。

  观察机器人的 TF 树，理解 `map → odom → base_footprint → base_link` 以及传感器坐标系之间的关系。在 README 中记录采用的环境方案、关键安装与构建步骤、软件版本、使用过的检查命令和遇到的问题，并展示 Gazebo、RViz、激光雷达和相机均正常工作的结果。
- **TASK2：设计机器人与仿真环境**

  修改提供的 Xacro、URDF 和 World 文件，设计属于自己的差速移动机器人及仿真场景。

  可以调整机器人尺寸、外观、传感器安装位置、场地结构、障碍物类型与分布，也可以创建或导入自己的模型。

  最终提交的机器人和场景不得保持起始工程原样。修改后应保证模型能够正常生成、轮式运动与传感器数据正常，且场景适合后续建图、探索和颜色跟随任务。
- **TASK3：手动控制与 SLAM 建图**

  启动 SLAM Toolbox，通过键盘控制机器人遍历自己设计的环境，完成一幅较完整的二维栅格地图并保存建图结果。

  建图过程中应尽量覆盖可通行区域，避免碰撞，并观察激光点云、机器人位姿、地图更新及回环修正。提交最终地图及建图过程的截图或视频，并简要说明遇到的问题和解决方法。
- **TASK4：SLAM 参数调节与对比**

  在成功完成基础建图后，根据自己的机器人和环境修改 `config/slam_params.yaml`。你可以调节地图分辨率、激光雷达有效范围、地图更新阈值、扫描匹配、回环检测或其他相关参数。

  至少完成一组调参前后的对比实验，保留两次建图结果，并说明修改了哪些参数、修改理由及其对地图质量和运行效果的影响。评价时更重视实验过程和分析，不以单纯堆叠参数数量作为标准。
- **TASK5：基于激光雷达的自主探索建图**

  自行编写 `exploration.py` ROS 2 节点，订阅 `/scan`，并向 `/cmd_vel` 发布 `geometry_msgs/msg/Twist`，使机器人能够在未知环境中自主移动、避障并完成建图，不再依赖键盘持续控制。

  基础实现可以比较前、左、右方向的测距结果，在接近障碍物时停止、后退或选择转向。有余力可进一步实现多区域感知、脱困策略、随机转向、速度控制、基于里程计的卡死检测、已访问区域记录或探索完成条件。程序退出或发生异常时必须主动发布零速度指令，使机器人安全停止。
- **TASK6：基于 OpenCV 的颜色目标跟随**

  自行编写 `color_follow.py` ROS 2 节点，订阅 `/camera/image_raw`，使用 `cv_bridge` 将 ROS 图像转换为 OpenCV 图像，并识别场景中的红色、绿色或蓝色目标。

  建议使用 HSV 阈值分割、形态学处理和轮廓分析获得目标位置与大小，再根据目标中心相对图像中心的偏差控制机器人转向。目标面积较大时应减速或停止；目标丢失时应停车或以较低速度搜索。程序应能应对一定程度的图像噪声，不得仅针对某一帧或固定坐标编写控制逻辑。
- **TASK7（附加题）：基于 Nav2 的自主导航**
  使用 TASK3 或 TASK5 建立并保存的二维栅格地图，配置 Nav2 导航系统，使机器人能够在已知地图中完成自主定位、全局路径规划、局部避障和运动控制。

  首先保存 SLAM 建图生成的 `.pgm` 和 `.yaml` 地图文件，并使用 Map Server 加载地图。使用 AMCL 或 SLAM Toolbox 定位模式确定机器人在地图中的位姿，在 RViz 中设置初始位姿后，通过 `Nav2 Goal` 或 `2D Goal Pose` 发布导航目标。

  Nav2 参数应根据 TASK2 中自行设计的机器人尺寸、运动能力和仿真场景进行配置，不得直接照搬起始工程中的全部默认参数。应重点检查：
  1. 机器人的 `footprint` 或 `robot_radius`；
  2. 最大线速度、最大角速度及加减速度限制；
  3. 全局代价地图与局部代价地图的尺寸、分辨率和更新频率；
  4. 障碍物层、静态地图层和膨胀层；
  5. `inflation_radius` 与 `cost_scaling_factor`；
  6. 全局规划器、局部控制器及其主要参数；
  7. 目标位置与目标姿态容差；
  8. 卡死、碰撞风险或规划失败时的恢复行为。

  至少设置三个具有不同位置和朝向的导航目标，使机器人在不依赖键盘持续控制的情况下依次到达目标点。导航路线中应至少包含一次明显转向，并经过一个障碍物附近或较窄的可通行区域。机器人在导航过程中应能够生成全局路径，根据局部环境调整运动，并避免与场景中的静态障碍物发生碰撞。

  在 RViz 中展示地图、机器人定位结果、全局路径、局部轨迹以及全局和局部代价地图，并提交完整导航过程的截图或视频。在 README 中说明全局规划器、局部控制器、全局代价地图和局部代价地图各自承担的作用。
