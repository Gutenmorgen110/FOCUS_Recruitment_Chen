1 项目整体说明

完成了 TASK 1 到 6，下面按照任务顺序进行说明。本说明提供 md 和 html 两个版本， 内容相同，但 md 版本无法流畅预览视频，所以推荐用 html 版本阅读。

1.1 怎么打开 html 版本

html 版在 html/ 目录下。不要直接双击 index.html——浏览器对 file:// 页面加载本地视频有安全限制，图片能正常显示、但视频会被拦掉，所以要借一个小型 本地服务打开。

Windows

  1. 双击 html/双击我打开网页.bat
  2. 浏览器会自动弹出，图片和视频都能正常播放，视频可以拖动进度条
  3. 看完关掉那个黑色命令行窗口即可

Linux

  1. 如果双击没反应：右键 → 属性 → 权限 → 勾选「允许作为程序执行」，再双击； 或者在该目录打开终端，执行 bash 双击我打开网页.sh
  2. 看完在终端里按 Ctrl-C 停止服务

手动启动

cd html
python3 serve.py        # Windows 上是 python serve.py

注：如果无法正常看到视频，检查网络并重新打开网页

6.5 设计思路

6.5.1 起点：三个数据 + 四个情境

最初的想法是写一个 count_range(起始角度, 终止角度)，对一段扇区输出三个量：

输出 用途
有效点个数 判断这段是否“有东西”

配一个 desicion_route 函数输出 Command(v, w)，另有 scan_cells 做网格化统计，订阅 /odom 判断是否到达目标点。默认直行；遇到情况三优先左转，左侧不安全再右转。

6.5.4 核心难题：怎么发现“墙上的缺口”

进入连廊之后，最紧要的问题变成如何探索房间。原来的策略是“优先直行”，但这样很多时候会错过左右侧的开口。

整理多次试验后发现的不足：

  • 判定安全时只依赖了“距离”这一个信息
  • 决定路线时只依赖了“优先前行”这一个策略

结果就是：自主探索会忽略进入小房间的那些微小空缺。 具体描述两个问题： 问题一（本质是信息不足） 有一段墙面有一个缺口，机器人沿着墙面直行，在墙面尽头遇到另一堵墙，减速。这个时候左侧是一个小房间，右侧是原本的空间。但机器人的微小倾角可能导致左侧距离远于右侧——这是一个概率性问题，也就是只通过这个时刻的数据无法判断是左行还是右行，所以策略必须能面对这种情况。

问题二（本质是无状态） 面对一个完整墙面时，机器人会反复摆头。猜测是由于转向操作改变了机器人状态，导致反复重复判断，最终卡死。这个地方最好留出一定的余量，方便进行运动控制。 初步的解决方向：

  • 问题二 → 加入 margin 阈值进行管理，或者通过状态机管理：如果开始旋转，那么一定要旋转到安全距离为止，而不只是旋转到减速状态
  • 问题一 → 引入时间变量，看能不能检测到左右侧出现距离突变的状态。比如扫描一段扇形中相邻帧（或者相邻五帧的平均值）的值差异，作差，看是否出现了普遍性的距离增大；如果是，说明遇到了空缺，可以探索

6.5.5 第一次尝试：跳变检测（最终被放弃）

贴着墙走记录数据，发现：前方足够靠近墙时，左右侧距离都会减小；而遇到空缺时，左侧距离会产生一个跳变，从 0.4 跳到 1.4。认为这个数据可以用来判断空缺。

这个地方需要存储历史信息，且最好保留最新的一组信息，那么很容易想到引入一个队列，先进先出。

经过反复思考，决定引入这个新策略：

当前方进入减速距离后，左右扫描，如果有一个方向出现跳变，优先走跳变方向；这个旋转一直旋转到前方到达一个安全阈值为止，这个值最好略大于减速距离。

但出现了新的问题：

  • 使用硬编码的方式，会出现面临小的空缺过不去
  • 又出现了在某一个角度卡死、左右反复转向的问题
  • 经常出现“转向不完全后直接向反方向旋转”的现象，所以想给系统添加一个记忆性，优先向历史方向旋转

这一步的教训：跳变检测是“事件触发”式的，它只在检测到变化的那一刻做决定；而机器人需要的是“当前哪个方向最好”的持续判断。事件式方案天生对时序敏感，帧率抖动、转向中途都会让它误判。

6.5.6 转折点：从“局部左右”到“全局最优”

继续测下去，暴露的问题越来越多：

（这一张是建图的时候被小房间卡死的记录） - 频繁碰撞 - 目前建图的问题在于只要进入小房间，就有较大可能被卡死，无法正常出来 - 面对障碍物时本来可以避开，结果一下转过头了，又从原路径返回 - 回退过程中没有检测后方障碍物，导致发生撞击，后续转向受到严重影响

（这一个是手动控制离开小房间后进行建图的结果） 阶段性总结成三条：

  1. 没有后方信息处理，无法在进入房间后进行有效回退
  2. 回退时往往会过于接近障碍物导致出现卡死状态；卡死时究竟往哪个方向转向，需要一个限制与约束
  3. 无法自主退出小房间，无法有目的性地向未探索区域前进

改进方向的设想：

  • 对问题一：按目前的思路，卡死状态加入一个新的特征——一是 360 度中存在足够近的点，二是进入卡死状态后，向最空旷的方向旋转，直到达到这个方向为止
  • 对问题三：目前无法解决

所以思路是，添加一个函数 scan_windows：扫描前方 180 度，哪个方向有最远的空缺。进而选择出最优的方向，而倒退交给前方 180 度没有任何办法前进的情况

总而言之，目前思考出来的一个改进思路就是：不从局部的左右出发，而采纳整体信息，每次卡死选择最优路径进行行走，而非只是局部的信息。

这一句话是整个设计的转折。 1. 方向决策从“左右二选一”变成“全向打分取最优” 2. 卡死判定从“局部特征”变成“全局状态” 3. 转向必须有状态（锁定目标角、转到位才停）

6.5.7 卡死与倒退的重构

整理思路，决定只修改转向部分逻辑，对这个地方进行重构，主要是卡死机制。后面更改了设计逻辑，采用各个方向。但由于进入和退出用了不同策略，会出现“退出转向时其实还没有脱离障碍物限制”的情况，目前是通过 odom 配合倒退机制进行操作。

但是这个往往无法正常退出房间。只能进行一个策略分类：通过将场景分为大房间和小房间两种状态——大房间内不存在 inf 或者间距极大的点，小房间中各个方向均能采集到信息，所以可以根据这个特征进行分析、判断。

目前暂时仍然无法解决。

6.5.8 仍未解决
