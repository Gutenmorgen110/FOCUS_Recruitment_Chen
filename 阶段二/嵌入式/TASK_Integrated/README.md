# TASK_Integrated — ESP32-S3 多模态控制终端

> ESP-IDF v5.5.4 · 目标芯片 ESP32-S3 · 最后更新 2026-10-05

## 一、项目简介

一块 ESP32-S3 上把「点灯 → 呼吸灯 → 串口控灯 → 无线控灯 → 直流电机调速 → 编码器 PID 闭环」全部收进同一个组件化工程，四路控制入口（串口 / 蓝牙 / 网页 / 板载）共用一套指令解析与同一份系统状态。

### 技术栈

| 层次 | 选型 |
|---|---|
| 主控 | **ESP32-S3-N16R8**（16 MB Flash + 8 MB Octal PSRAM，双核 240 MHz） |
| 框架 | **ESP-IDF v5.5.4** 原生（非 Arduino / PlatformIO） |
| 系统 | FreeRTOS，tick 1000 Hz |
| 外设驱动 | `esp_driver_gpio` · `esp_driver_ledc` · `esp_driver_uart` · `esp_driver_pcnt` |
| 网络 | `esp_wifi`（STA）· `esp_http_server` · `esp_event` · `nvs_flash` |
| 电机驱动 | **TB6612FNG** |
| 蓝牙 | **HC-04D**（UART 透传，不启用 ESP32 蓝牙协议栈） |

> **本工程未包含 LVGL / EEZ Studio / 触摸屏**——TASK6 为选做加分项，未纳入本次整合范围。

## 二、硬件引脚

### 2.1 外接 LED

| 信号 | GPIO | 方向 | 说明 |
|---|---|---|---|
| LED | **8** | 输出 | LEDC TIMER_0 / CH0；阳极接 GPIO8，阴极经限流电阻到 GND |

限流电阻取 330 Ω ~ 1 kΩ 均可（ESP32-S3 单脚绝对最大 40 mA），越小越亮。
⚠️ **建议用红/黄/绿 LED**（正向压降约 2 V）。蓝/白 LED 的压降接近 3.3 V，同一电阻下电流极小、几乎看不见。

### 2.2 电机驱动 TB6612FNG

| 信号 | GPIO | 方向 | 说明 |
|---|---|---|---|
| PWMA | **4** | 输出 | 调速 PWM，LEDC TIMER_1 / CH1 |
| AIN1 | **5** | 输出 | 方向电平 |
| AIN2 | **6** | 输出 | 方向电平 |
| STBY | **7** | 输出 | **必须拉高**，否则整片芯片待机、电机完全不动 |

`AIN1`/`AIN2` 电平组合：`1/0` 正转，`0/1` 反转，`0/0` 滑行。转反了把 `AO1`/`AO2` 对调即可。
B 通道（`BIN1`/`BIN2`/`PWMB`/`BO1`/`BO2`）本工程未使用，悬空。

### 2.3 编码器

| 信号 | GPIO | 方向 | 说明 |
|---|---|---|---|
| ENC_A | **15** | 输入 | PCNT unit0，开内部上拉 |
| ENC_B | **16** | 输入 | 同上 |

⚠️ **编码器 VCC 优先接 3.3 V**。若模块只支持 5 V，A/B 两相各加分压（10 kΩ / 20 kΩ），否则 5 V 逻辑会灌进 GPIO。**上电前先用万用表量 A/B 对地电压确认 ≤ 3.3 V。**

### 2.4 蓝牙 HC-04D

| 信号 | GPIO | 方向 | 说明 |
|---|---|---|---|
| UART1 TX | **17** | 输出 | → 模块 **RXD**（必须交叉） |
| UART1 RX | **18** | 输入 | ← 模块 **TXD** |

GPIO17/18 是 UART1 的 IO_MUX 默认脚，板上没有任何其他外设占用，接蓝牙不用走 GPIO 矩阵。

⚠️ **TX/RX 必须交叉**，且模块与开发板**必须共地**。模块 `VCC` 按丝印：标 `3.3V` 接 3V3，标 `3.6~6V` 接 5V。

⚠️ **绝对不要接到 GPIO43/44（UART0）**。双 USB 口的开发板在那两个脚上焊了 USB 桥接芯片（CH343/CP2102），
再接蓝牙就等于**两个输出脚驱动同一条线**：模块想拉低、桥接芯片把它拽高，ESP32 收到的全是乱码。
实测症状是「手机发指令一律回 `ERROR`、电脑日志却毫无反应」。

### 2.5 日志 / 调试口

**无需接线**。日志已从 UART0 挪到 **USB-Serial-JTAG**（GPIO19/20，板上的原生 USB 口），
`idf.py monitor` 直接就能看：

```
idf.py -p /dev/ttyACM0 flash monitor
```

⚠️ 这个口**只出日志，不进指令**（本工程没在它上面装命令行）。指令一律从蓝牙走。

### 2.6 电源接线

```
5V 独立电源 ─┬─ TB6612 VM（电机功率）
             ├─ TB6612 GND ──┬── ESP32 GND（必须共地）
             └─ TT 电机
ESP32 3V3 ───┬─ TB6612 VCC（逻辑电源，2.7~5.5V）
             └─ 编码器 VCC（优先 3.3V，见 2.3）
```

TB6612 的 `VM`–`GND` 之间并 **100~470 µF 电解 + 100 nF 陶瓷**。

⚠️ **不要用开发板的 5V 引脚给 VM 长期供电**：电机启动/堵转电流是 1 A 量级，会把 USB 5V 拉塌导致 ESP32 欠压复位（现象：串口突然重打印启动日志）。

### 2.7 已占用的引脚（回避清单）

| 类别 | GPIO |
|---|---|
| SPI0/1 Flash | 26–32 |
| **Octal PSRAM（N16R8 必避）** | **33–37** |
| Strapping | 0, 3, 45, 46 |
| USB-JTAG | 19, 20 |
| 板载 WS2812（部分 DevKitC-1 版本） | 38 或 48 |
| **USB 桥接芯片（双 USB 口板子）** | **43, 44** |

## 三、关键参数

### 3.1 PWM

同一 timer 下的通道必须共用同一频率，所以 LED 与电机分到两个 timer：

| 用途 | Timer / Channel | 频率 | 分辨率 | 选值理由 |
|---|---|---|---|---|
| LED | TIMER_0 / CH0 | **5 kHz** | **13 bit** | 人眼无频闪，8192 级渐变平滑 |
| 电机 PWMA | TIMER_1 / CH1 | **20 kHz** | **10 bit** | 20 kHz 高于人耳听阈，消除 PWM 啸叫 |

10 bit 是被 20 kHz 逼出来的硬约束：`20 kHz × 2¹³ = 163.84 MHz > APB 80 MHz`，物理上做不到，而 `80 MHz / (20 kHz × 1024) = 3.90625` 可被 LEDC 的 8 位小数分频精确表达。

⚠️ **不要开 `CONFIG_PM_ENABLE`（DFS）**，否则 APB 变频会让 LEDC 占空比跟着跳变。

### 3.2 编码器

| 参数 | 值 | 说明 |
|---|---|---|
| 每转脉冲 `ENCODER_PPR` | **44** | 11 线 × 4 倍频 |
| 采样周期 | **50 ms** | 专用的 `encoder_rpm` 任务 |
| PCNT 计数上下限 | ±100 | 开 `accum_count`，溢出由驱动自动累加，无需 ISR |
| 毛刺滤波 | **12500 ns** | 等效原实现的 1000 个 APB 周期 @80 MHz |

测速公式：

```
RPM = Δcount × 60000 / (ENCODER_PPR × 减速比 × 采样周期ms)
```

⚠️ **减速电机必须乘减速比，且 PPR 要按实物标定**——手转 10 圈读 Δcount 求平均，不要照抄典型值。

### 3.3 PID

| 参数 | 值 |
|---|---|
| Kp | **0.0025** |
| Ki | **0.0015** |
| Kd | **0.0** |
| 积分限幅 | ±200 |
| 输出限幅 | 0.0 ~ 1.0（占空比） |
| 控制周期 | 20 ms |
| 闭环日志间隔 | 200 ms |

⚠️ **以上三个系数是占位值，必须用实物整定。** 整定流程：

1. I = 0、D = 0，P 从小到大（每次 ×1.5）找到明显震荡的 P
2. 取该值的 50% ~ 60%
3. 加 I 消除稳态误差
4. 需要时加微小 D 抑制过冲

若时间不够，**冻结为 P-only** 也比硬凑一个发散的 PID 好——有真实的 RPM 曲线远胜于一个跑不起来的闭环。

### 3.4 串口

| 端口 | 用途 | 波特率 | 帧格式 | 流控 |
|---|---|---|---|---|
| UART1（GPIO17/18） | HC-04D 蓝牙透传 | **9600**（Kconfig 可改） | 8N1 | 无 |
| USB-Serial-JTAG | 日志输出（只出不进） | — | — | — |

HC-04D 出厂默认就是 **9600**，本工程直接跟它对上，**不需要先用 AT 指令去改模块**。
若模块此前已被改成其他波特率，在 `idf.py menuconfig → TASK_Integrated → HC-04D 波特率` 同步即可。

控制台配置（`sdkconfig.defaults`）：

```
CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG=y      # 日志走原生 USB
# CONFIG_ESP_CONSOLE_UART_DEFAULT is not set
CONFIG_ESP_CONSOLE_SECONDARY_NONE=y
```

⚠️ 这样改的原因是 **UART0 被蓝牙占用了**。如果保持控制台在 UART0，日志会和蓝牙指令挤同一条线，
手机端会看到一堆混杂的 `I (xxx) ...` 日志。现在日志走电脑、指令走手机，两条通道完全分开。

### 3.5 其他

| 项 | 值 |
|---|---|
| 电机自动渐变档位 | 30% → 60% → 90% → 60%，每档 2 s 循环 |
| FreeRTOS tick | 1000 Hz |
