# FOCUS 2026年秋季招新控制组第一阶段考核（9.7 - 9.17）

## 考核内容一：基础政策与原则

  请认真阅读并理解以下基础政策和原则，确保不违背本次招新的根本精神。

### 考核目标

  满足以下要求之一即可：

1. 选拔出具有自驱力、对机器人方向怀有足够热爱，愿意在此领域投入大量时间和精力的人才（而非过于功利、唯加分或评奖评优论者）。
2. 选拔出敢于尝试、不墨守成规，愿意在大学阶段积极探索技术、创业或科研方向的人才。
3. 选拔出具备组织、表达、团结与领导能力，能够带动身边队友共同进步、协调项目进度的人才。
4. 选拔出深造意愿强烈，对攻读博士、从事科研工作充满热情的人才。

### 出题原则

1. 假定参与考核的同学为有志于往机器人方向发展的大学一年级新生。考核内容旨在补全机器人从业者及机器人专业学生所必需且共通的底层能力与视野，帮助其对未来的机器人学习路线形成初步规划。
2. 假定学生具备科学上网能力，并能够使用AI工具（若尚不具备，需主动向周围同学请教学习）。
3. 不假定学生具备中等及以上的基础能力（即不假定其在高中参加过机器人或信息学相关竞赛，或接触过任何编程语言）。

### AI 使用政策（AI Policy）

1. 本说明适用于本次考核全程及全部内容。
2. 你可以、也应当将AI视为能力远超于你的协作者或老师，应经常向其请教问题，将其作为你最得力的帮手。
3. 但在此次考核中，你绝不能将自己定位为产品经理、将AI定位为工程师来直接交付结果，否则你将无法从中获得真正的成长。
4. 若完全依赖 Codex、Claude Code 等 AI 代码工具生成代码，而自身对基础细节一无所知，情节严重者将视为作弊，直接淘汰。
5. 对于环境配置等问题，你可以尽情地使用AI。
6. 所有人所使用的AI能力相同或接近，真正区分你与他人的，是基本功。

### 任务注解

1. **关于 Git 操作**：你只需要理解如何上传代码和创建仓库即可。对于具体的 Git 命令操作，我不做硬性要求。你只需跟着第二个学习资料跑一遍，建立感性认知就可以了。事实上，在未来的很长一段时间里，你可能都用不到复杂的 Git 命令操作，而且你可以使用很多 UI 化的界面来代替命令行操作，比如 **GitHub Desktop**。需要说明的是，Git 本身并不简单——至少你得知道它是一个**有向无环图（DAG）**，这才算真正入门了。
2. **学习日志要求**：你每天都应该写一篇不超过 200 字的学习日志，内容包括：

   - 是如何解决的；
   - 具体学到了什么；
   - 有什么想法或思考。
3. **预计时间**：本任务预计 **1 天** 完成。
